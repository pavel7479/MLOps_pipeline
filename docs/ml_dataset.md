# Контракт ML-dataset

Этот документ фиксирует семантику времени и доступности данных в ML-dataset Блока 2.

## Timestamp свечи

Колонка `timestamp` хранится в UTC и идентифицирует свечу. Для данных Binance это время открытия свечи, а не момент готовности прогноза.

Для timeframe `1h` строка с `timestamp = 2026-01-01 12:00 UTC` соответствует свече, которая формируется на интервале `[12:00, 13:00)` и считается доступной только после её закрытия в `13:00 UTC`.

## Момент выполнения прогноза

Все признаки строки `t` рассчитываются по полностью закрытой свече `t` и закрытым свечам до неё. Значения OHLCV свечи `t` разрешено использовать, потому что inference выполняется только после её закрытия.

Следовательно:

```text
feature_cutoff(t) = close_time_of_candle(t)
prediction_time >= close_time_of_candle(t)
```

Pipeline не предназначен для внутрисвечного inference. Частично сформированные `high`, `low`, `close` или `volume` текущей незакрытой свечи не должны подаваться модели как строка `t`.

## Прогнозируемая величина

Базой прогноза является `close[t]`, то есть окончательная цена закрытия текущей свечи. Target измеряет изменение до закрытия свечи на настроенном горизонте:

```text
future_return[t] = close[t + horizon_periods] / close[t] - 1
```

Для текущей конфигурации:

```text
timeframe = 1h
target.horizon_hours = 3
horizon_periods = 3
```

Таким образом, модель отвечает на вопрос: «Как изменится Close через три часа относительно уже известного закрытия текущей свечи?»

Классификация:

```text
future_return >= buy_threshold   -> BUY
future_return <= sell_threshold  -> SELL
otherwise                        -> HOLD
```

`future_return` и `target` используют будущую цену и поэтому не входят в `features` файла `feature_manifest.json`.

## Пример временной линии

Для строки `t = 12:00 UTC` и timeframe `1h`:

```text
12:00              13:00                              16:00
| candle t --------| prediction becomes available     | horizon Close
                    baseline = close[t]                 close[t + 3]
```

Признаки строки `t` не могут использовать значения после закрытия свечи `t`. Target этой строки использует `close[t + 3]` исключительно как учебную метку.

## Split и purge

Train, Validation и Test разделяются хронологически. Последние `horizon_periods` строк Train и Validation удаляются. Purge гарантирует, что будущая цена, используемая target последней сохранённой строки предыдущего split, не попадает во временной диапазон следующего split.
